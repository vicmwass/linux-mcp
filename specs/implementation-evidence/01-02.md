# Spec 01 step 01-02 evidence

## Scope

Bootstrapped `linux-mcp-inventory` with typed PostgreSQL configuration,
compile-time SQLx migrations, and placeholders for the separately owned
repository, credential, trust, destination, and resolver modules.

## Artifacts

- `Cargo.toml` workspace registration for `crates/inventory`
- `Cargo.lock` SQLx dependency resolution
- `crates/inventory/Cargo.toml`
- `crates/inventory/README.md`
- `crates/inventory/src/{lib,config,migrations,repository,credentials,trust,destinations,resolver}.rs`
- `crates/inventory/migrations/202610110001_inventory_servers.sql`
- `crates/inventory/migrations/202610110002_inventory_credentials.sql`
- `crates/inventory/migrations/202610110003_inventory_host_trust.sql`
- `crates/inventory/migrations/202610110004_inventory_invalidations.sql`

The migration set is namespaced to the inventory crate and preserves the
installation/owner boundaries, server revisions, encrypted credential envelope
metadata, host-trust state, and invalidation event stream from the design.

## Limitations

No PostgreSQL service or disposable database URL is configured in this
environment, so fresh migration/reapply execution was not run. The embedded
SQLx migrator compiles and the migration files are present; database execution
is required in the integration gate.
