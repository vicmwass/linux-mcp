# Spec 01 step 01-04 evidence

## Scope

Implemented the inventory credential encryption boundary with an external key
provider, AES-256-GCM authenticated envelopes, metadata-bound associated data,
key rotation, bounded plaintext size, and redacted diagnostics.

## Artifacts

- `crates/inventory/Cargo.toml`
- `crates/inventory/src/credentials.rs`

The envelope authenticates installation, owner, server, credential, kind,
revision, and format metadata. Missing keys, malformed envelopes, tampering,
foreign metadata, and oversized secrets fail closed. Rotation decrypts only
through the old external key and re-encrypts under a new key ID; no plaintext
fallback exists.

## Validation

- `cargo fmt -p linux-mcp-inventory -- --check` — passed.
- `cargo test -p linux-mcp-inventory --locked` — passed; 9 tests.
- `git diff --check` — passed.

Focused tests cover authenticated round-trip, ciphertext tampering, foreign
owner metadata, missing keys, key rotation, secret size limits, and redacted
credential debug output.

## Limitations

The PostgreSQL repository integration and credential lifecycle transaction
coordination are implemented by later Spec 01 repository/resolver steps. The
key provider in these tests is an in-memory fake and contains only test
markers, never real credentials.
