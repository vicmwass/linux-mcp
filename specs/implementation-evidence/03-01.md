## Scope

Recorded current execution behavior and designed the extraction of `crates/execution-core` against the frozen Spec 00 contracts. Documentation only.

## Key findings (all read from source at 31fb043)

- Capability cache and connection pool are keyed by server ID / `server_id::username` only; host trust is a process-wide known_hosts file; secrets are file paths; output limits are declared but not enforced; errors after `channel.exec` (including a missing exit status) are generic failures that must become unknown-after-submission.
- The frozen `Executor` trait has no classification step, so the executor must recompute risk/resolved arguments and an additive planner is needed (no contract change).
- Host-key observation and connect-time destination checks need transport primitives that Spec 01 must reach through an interface; recorded as open question Q-03-1 (needs an additive contracts extension request before implementation).

## Limitations

- Whether russh reports an explicit failure reply to an exec request that could justify a definite non-execution outcome is unverified; the design treats every post-exec error as unknown.
- Concurrency defaults (4 per user) are recommendations pending 03-06.
- The live verify_* scripts were not run (they need configured hosts and are final-gate checks).
