# Spec 01 step 01-01 evidence

## Scope

Mapped the frozen Spec 00 inventory, resolver, credential, trust, revision,
invalidation, and approval-mode contracts into an implementation design for
`crates/inventory`.

## Artifacts

- `specs/design/01/README.md`
- `specs/design/01/schema.md`
- `specs/design/01/secrets-and-trust.md`
- `specs/design/01/destination-policy.md`
- `specs/design/01/acceptance-matrix.md`

The design covers installation/owner isolation, CRUD and pagination, revision
transactions, invalidation events, authenticated encryption, external key IDs,
rotation/recovery, bounded secret leases, host-key observation versus trust,
DNS/address policy, deletion cleanup, and the per-server approval-mode
extension.

## Validation

- Read and matched the frozen contracts in
  `crates/contracts/src/backend/services.rs`,
  `crates/contracts/src/backend/target.rs`,
  `crates/contracts/src/backend/credentials.rs`,
  `crates/contracts/src/public/inventory.rs`, and
  `crates/contracts/src/public/api.rs`.
- Verified primary dependency documentation:
  - SQLx: <https://docs.rs/sqlx/latest/sqlx/>
  - RustCrypto AES-GCM: <https://docs.rs/aes-gcm/latest/aes_gcm/>
- No product code or dependency manifests were changed.
- Documentation-only step; no test command was required.

## Limitations

The SQL migrations, repository, crypto adapter, destination evaluator, and
management handlers are intentionally deferred to steps 01-02 through 01-07.
No live PostgreSQL, key provider, DNS resolver, or external machine was used.
