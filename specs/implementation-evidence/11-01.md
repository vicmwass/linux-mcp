# Spec 11 step 11-01 evidence

## Scope

Defined and froze the bounded workflow contracts for Package A (deterministic guided workflows): template, run progress and fleet comparison schemas, closed step/parameter vocabularies, lint rules, run state machine with safe resumability, and fleet partial-result semantics. Documentation and design fixtures only; the optional WebMCP and embedded-assistant packages were not touched.

- Relative links in the four documents resolved.

## Acceptance

- Dynamic unapproved shell instructions cannot become steps: no command-bearing step or parameter type exists; denied-tool and parameter-name rules; four fixtures.
- Mutation authority stays with approval/policy: mutate steps only prepare Spec 06 intents; no approval field exists anywhere; read-only integrity rule L8.

## Limitations and open items

- Tool IDs and argument names from Specs 08 and 10 are provisional until 08-01/10-01 freeze them.
- The shared contracts crate was not changed: the public workflow DTOs need an additive contracts extension (`public::workflows`, CONTRACT_VERSION 1.1.0, FROZEN manifest update) executed under the contracts owner's process in 11-02 or a dedicated step. The `contracts-registry` reservation was held but unused.
- The Python validator is design evidence, not the runtime validator; the Rust runner must re-implement the same rules against these fixtures.
- The dashboard presentation of `suggest` and fleet partial results is described but not designed (Specs 05/12).
