# Spec 02 step 02-01 evidence

## Scope

Selected the identity provider and defined the authorization flows, claims, subject mapping, session model and revocation design for `crates/identity`. Documentation only.

## Artifacts

- `specs/design/02/README.md` — decision summary, provider evaluation, conditions, Rust libraries, named target clients, sources, open items
- `specs/design/02/flows.md` — installation model, dashboard login, remote-agent authorization, delegated dashboard authority, authority kinds, subject mapping, expected claims
- `specs/design/02/revocation-and-sessions.md` — MCP-revision session handling, 60-second revocation design, logout versus grant revocation, theft hygiene
- `specs/design/02/acceptance-matrix.md` — Spec 02 requirement → step → proof

## Decisions

- Provider: Keycloak, one realm per installation; no custom OAuth protocol.
- Baseline uses only features the Keycloak guide labels Supported (OAuth 2.1, RFC 8414, RFC 9207, DCR) plus the scope→audience mapper; RFC 8707 and CIMD (labeled Experimental) are optional installation settings.
- Target MCP revision 2025-11-25, designed to be sessionless-compatible with 2026-07-28.
- Delegated dashboard authority via the dashboard's own authorization-code grant for the MCP resource; token exchange left as an option to verify in 02-05.

## Validation (research, performed 2026-10-11)

- Read the official MCP authorization pages for 2025-11-25 and the latest (2026-07-28) and the official 2026-07-28 changelog. Finding that changes the plan: sessions and the `initialize` handshake are removed in 2026-07-28; DCR is deprecated in favor of Client ID Metadata Documents; `iss` validation (RFC 9207) added.
- Read Keycloak's own MCP guide (documents nightly 26.8.0): conformance labels and enabling flags recorded in README.md.
- Ory Hydra and ZITADEL status came only from a third-party comparison table and web summaries; recorded as unconfirmed leads, not as verified facts.
- Checked crates.io metadata for `jsonwebtoken` (11.1.0), `openidconnect` (4.0.1), `rmcp` (3.5.1; lockfile has 3.2.0).
- No product code or dependency manifest changed; no test command applies.

## Limitations

- The Keycloak released version to pin is not selected; the guide documents a nightly. Spec 07 must verify against release notes.
- rmcp support for the 2026-07-28 revision is unverified (04-01).
- No MCP client was run against any provider; the named-client list is provider-guide documentation, not our verification.
- Authentik, Dex and Logto were not evaluated; the choice is reversible because the resource server depends only on standards.
- Keycloak is not a Rust component and adds an operated service (decision flagged for the product owner; not a blocker).
